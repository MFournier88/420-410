# 📝 Examen : Le Système d'Ambiance "Neo-Mood-AP"
### Matériel autorisé :
- Site du cours
- Raspberry Pi et composants
- Cellulaire (pour test de l'interface uniquement)
- W3Schools pour le JavaScript uniquement

**Contexte :** Vous devez configurer un Raspberry Pi pour piloter un système d'éclairage à deux canaux : un canal **"Ambiance Chaude"** et un canal **"Ambiance Froide"**, contrôlés par une interface web mobile sécurisée par un interrupteur physique.

### 1. Configuration Réseau et Serveur 
* **Mode Point d'Accès (AP) :** Le SSID doit être `Exam-NeoMood-VOTRENOM`.
* **Réseau :** Configurer une adresse IP statique : `192.168.22.1`.
* **Serveur :** Flask doit écouter sur le port `8080`.

### 2. Montage Électronique 
* **Bouton :** Branché sur le **GPIO 6** (Contrôle global ON/OFF).
* **LED RGB #1 :** Vert ➔ **26** | Rouge ➔ **19** | Bleu ➔ **13**
* **LED RGB #2 :** Vert ➔ **21** | Rouge ➔ **20** | Bleu ➔ **16**

### 4. Travail Backend (app.py) (14 pts)

#### A. Logique Flask & PWM (8 pts)
Votre script Python doit gérer l'allumage des LEDs en respectant les ratios de couleurs suivants (basés sur la valeur `intensity` reçue du web) :

* **Route `POST /api/update_mood` :**
    * **Canal 1 (Chaud) :** Rouge = `val` | Vert = `val * 0.5` | Bleu = `0`
    * **Canal 2 (Froid) :** Rouge = `val * 0.2` | Vert = `val * 0.8` | Bleu = `val`
* **Route `GET /api/hardware_status` :** Doit retourner un JSON `{"active": true/false}` selon l'état actuel du système.

#### B. Logique du Bouton "Kill-Switch" (6 pts)
* L'appui sur le bouton (GPIO 5) doit basculer (Toggle) l'état du système.
* **État SÉCURITÉ :** Toutes les LEDs s'éteignent immédiatement et **les commandes web sont ignorées**.
* **État ACTIF :** Les LEDs reprennent leurs couleurs ou acceptent de nouvelles commandes.
